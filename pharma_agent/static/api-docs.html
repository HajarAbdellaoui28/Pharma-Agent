DEVELOPER REFERENCE

The research API.

Same-origin JSON endpoints. No additional services required.

OpenAPI schema ↗

GET /health

Returns HTTP 200 for liveness. Inspect ready before research; it is false when corpus or provider initialization is unavailable.

{"status":"ok","ready":true,"research_status":"ready","documents":21,"chunks":510}

POST /ask

Request: a question with 3–2,000 characters. Unknown fields are rejected.

{"question":"What are the main contraindications for warfarin?"}

Response fields: answer, status (verified or limited), citations, sources, plan, workflow, limitations, metrics, and disclaimer. Citations identify a chunk, source file, section, lines, source URL, and exact supporting quote.

Research runs synchronously. Allow up to 240 seconds with default settings. A verified status means source review passed; it does not establish clinical validity.

GET /sources/{chunk_id}

Returns the indexed source passage with its original character offsets and source metadata. Unknown identifiers return HTTP 404. The endpoint never opens user-supplied file paths.

Errors

HTTP 413: oversized body. HTTP 422: invalid request. HTTP 503: corpus or provider unavailable. HTTP 504: research timeout. HTTP 500: unexpected failure with a sanitized message.

This demo has no account authentication. Add authentication, per-user quotas, and a reverse proxy before exposing a deployment publicly.

Command-line example

curl -X POST http://localhost:8000/ask \
  -H "Content-Type: application/json" \
  -d '{"question":"What are the main contraindications for warfarin?"}'

For research and education. Not medical advice.
